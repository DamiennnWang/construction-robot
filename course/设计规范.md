# 课程页面设计规范

适用于全部任务页。对象是中职学生；页面是“边动手、边看结果”的数字教材互动页，不是说明书，也不是教材的翻版。第二章是第一个按本规范整理的章节，可作为样板。

## 1. 页面只做一件事：让学生动手玩模型

- **不写“学习目标”“学习任务”“学习引导”“本节学什么”**，也不设这类标签页或弹窗。
- 面板内容**自由设计**，不必按教材的段落或“任务实施”顺序排；教材以后再按页面修订。宁可发散、有趣，不要像教材一样死板。
- 页面上的文字只有三种：**现在可以做什么**（一句话引子、控件名）、**看到了什么**（读数、提示条）、**部件叫什么**（名称和一句作用）。
- 每个任务页分成 2～3 个**工位**。一个工位 = 一台三维模型 + 几个动手控件 + 几张“试一试”挑战卡。
- **试一试**：3～4 张小挑战（如“让它反着转”“把它憋停”“猜中升高的距离”），每张带一个图标，不分先后，模型状态满足条件就自动打勾，并在三维区上方弹出一句“为什么”。挑战全部完成后，工位标签打 ✓。
- 原模型自带的动手模式（如电机的“组装与接线”、柴油机的“拆开/装进挖掘机”）放在本工位里，用挑战卡上的按钮进入，不另开工位。同一章里相似的东西结构要对称。
- 可以有“先猜后验证”的小互动（填一个数，模型跑给你看），但不出整套题。

## 2. 菜单最多两层

1. 页头：本章任务（如 2-1 / 2-2 / 2-3）。
2. 工位条：本任务的 2～3 个工位，带完成标记 ✓。

面板里**不出现标签页、子标签、折叠菜单**，也不放说明弹窗。和“怎么看”有关的开关（剖开、视角、受力线、轨迹）放在三维区左上角；运行、单步、复位、快慢放在三维区底部；面板只放“改变条件”的控件和挑战卡。同一个功能只出现一次，不在面板和画面里各放一份。

## 3. 一屏放下：16:9 屏幕不上下滚动

- 目标是**不出现页面纵向滚动条**，而不是把画面锁死成 16:9。
- 必须在这些浏览器可视区域内完整显示、页面和面板都不滚动：1920×950、1600×780、1440×780、1366×640（已扣除浏览器地址栏与任务栏）。
- 做法：页面高度 = 视口高度（`100dvh`），三维区吃掉剩余空间；面板只放 2～3 组控件 + 挑战卡；反馈用三维区上方的提示条，几秒后自动收起，不挤占面板。
- 宽度小于 900px（平板竖屏、手机）时改为上下排列，允许整页滚动。

## 4. 统一外观

| 项目 | 规定 |
| --- | --- |
| 网页标题 | `任务编号 任务名｜智能建筑机械与机器人`，任务名与 `course/catalog.json` 一致 |
| 页头 | 左：返回本章；中：本章任务；右：深浅色切换。无英文小标、无图标徽章 |
| 工位条 | 左侧“任务编号 + 任务名”，右侧工位按钮 `① 名称 ✓` |
| 布局 | 左侧三维区（约 70%），底部一条“运行 + 读数”（最多 4 个读数）；右侧操作面板（宽 330～400px） |
| 面板 | 编号徽标 + 工位名 + 一句引子（右上角“↺ 重来”）→ 2～3 组控件（标题前有主色短竖条）→ 试一试（进度条 + 图标挑战卡） |
| 质感 | 卡片圆角 16px、柔和投影；主按钮和选中工位用蓝色渐变；滑块已走过的一段填主色；读数做成等宽小方块铺满底栏 |
| 主色 | 全课程一个蓝 `#2467c9`（深色模式 `#8abaff`），各章不换主色 |
| 状态色 | 绿 `#1f8a5b` 完成/正确；橙 `#c77a12` 注意；红 `#c2413b` 错误/危险 |
| 关注色 | 琥珀色 `#f0a020`，只用于“现在要看的那个部件” |
| 按钮 | 每个面板最多一个主按钮（实心蓝）；按钮文字不超过 6 个字 |
| 字体 | 微软雅黑 / 苹方，正文 14～15px，读数数字 19px 以上 |

## 5. 三维模型

- **已有的三维模型和动画一律保留，不重做。** 只有用户明确要求、或模型确实错误时才改模型本身。
- 新外壳通过嵌入复用原模型：原版实验页照常构建，任务页用 iframe 打开它，`shared/动力与工作机构/embed-bridge.js` 在嵌入时只留下三维视图，并用 postMessage 接收面板命令、回报模型状态（file:// 离线打开同样可用）。原版页面单独打开时不受影响。
- 读数和挑战判定都来自原模型自己的状态（如 `motorLab.getModel()`、`MechanicsLab.snapshot()`），不在外壳里另算一套。
- 模型的字母、编号与教材插图保持一致（如油口 P/T/A/B）。
- 新做的模型才需要遵守：真实材质、剖视截面用浅杏色、同时显示的标签不超过 5 个。教材平面原理图的交互版可用 anatomy 等轴图风格（`shared/anatomy/`）。

## 6. 内容尺度

- 一句话能说清的就不写两句。挑战卡的提示 ≤ 15 字，完成后的解释 ≤ 2 句。
- 每个工位最多用一个公式，且是教材里有的（如 i = z₂ / z₁，移动距离 = 圈数 × 导程）。
- 数值取整数或一位小数，必须带单位。不出现教材以外的理论术语。
- 不伪造真实设备性能、安全结论或检测结果。

## 7. 进度

- 工位挑战全部完成后打 ✓，进度只存本机浏览器；“↺ 重来”把工位恢复到初始状态。
- 不计时、不排名、不扣分。

## 原地模式改版做法（第三章经验，第四章起照此执行）

**接入**：在任务自己的 `build.mjs` 里，原页面生成完后调用 `labShell(html, task, page)`（`import {labShell, hasStations} from '<相对路径>/shared/lab-shell/native-layout.mjs'`）。有 `stations.js` 时不再套原来的章节版式（`chapter-layout.mjs` 的 1600×900 外框），参照 `shared/机器人构型与运动/src/chapter-layout.mjs` 的写法。workshop 页面只需写 `src/stations.js`，再 `python scripts/build-workshops.py <任务号>`；它们的页面是脚本运行时才建出来的，`stations.js` 要等原页面的关键元素出现后再调 `NativeShell.start()`。

**stations.js 骨架**（`window.NativeShell`，第三章的 `C3Shell` 是同一个对象）：
- 启动时一次性缓存要用的元素引用（`EL = {...}`），不要在工位切换后再查选择器——被搬走的元素会被“停放”回隐藏容器。
- `stage`：原页面的三维区；`stageTop`：三维区上方的一排“选研究对象”控件（构型、底盘、工具等），按工位用 `hidden` 显隐。
- `stations`：原页面的页签/活动/模式就是工位（2～4 个）。`current()` 读原页面当前活动，`select(id)` 调原页面的切换（按钮 `.click()` 或接口）。
- 每个工位 `build(c)`：`c.section('标题')` 建一组，`c.adopt(元素, 组)` 把原控件搬进来；`c.challenges([...])` 做“试一试”，`check(state)` 读原页面状态，必要时监听原按钮的点击记标记。
- `poll()` 每 200 ms 返回原页面的状态对象（原页面接口 `xxxLab.getState()` 等）；原页面的提示条（`#notice` 之类）文字变化时转成 `c.feedback(文字, 'info'|'warn')`。
- `reset`：接原页面的复位。

**内容**：
- 原页面的内容主体、三维模型、动画都保留，不重做；只是重排版、去掉大段说明。原页面自带的关卡/挑战直接做成“试一试”卡片，完成记录沿用原页面的存储。
- 去掉：学习目标/任务/引导文字、导语卡、“下一步/去闯关”之类跳转链接、键盘说明、重复的标题和读数。
- 不要三维区下方的底栏控件条（3-2 已被否定）；运行/读数可放三维区底部原有位置或面板里。选对象的控件放三维区上方。
- 面板可以比一屏略长（面板内部滚动），页面本身不滚动。
- 原页面明显不合理的内容（与前后章重复、术语超纲、和别章机型不一致）**先不要改**，在报告里列出来，等用户确认。

**常见坑**：
- 原 CSS 给列表/卡片写死了 `grid-template-rows`、`height`，搬进面板后被拉伸——在 `stations.css` 里用 `grid-template-rows:none!important; grid-auto-rows:auto!important; height:auto!important` 复位。
- 原页面的 `main` 网格会影响外壳，`lab-shell.css` 已加固；三维区切工位后空白时外壳会补发 resize（60/300/900 ms）。
- 被 `stripAdopt` / `adopt` 的节点必须由外壳停放，不要 `replaceChildren` 掉，否则原页面的 `stop()` 之类会找不到元素。
- 后台标签页不跑 requestAnimationFrame，不要用它判断“页面已就绪”。
- 原页面自带的 SVG `NaN` 控制台报错（3-3、3-4 已有）不是外壳造成的，先对照原版本确认。

**验收**：1440×810 与 1366×640 下页面不滚动；每个工位都切一遍、“试一试”至少实际触发一张；深色模式看一眼；外壳不产生新的控制台报错；`node scripts/test.mjs` 全过。

**构建与提交**：
- 构建后运行 `python scripts/finalize-pages.py`，再把与本任务无关的变动全部还原（它会重写其他章节的页面：`git checkout -- <其他目录>`），提交里只能有本任务目录下的文件。
- 每个小节在自己的分支 `chN/x-x` 上提交一次（中文提交说明），全章完成后由主会话合并进 V3 再提交一次。只在本地提交，不 push。
